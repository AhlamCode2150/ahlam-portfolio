IV Method

        
How a folio gets made

      

      
    
        
  1. 01
    Notice the itch
    Most projects start with my own problem. TOTA exists because I kept forgetting to eat while working.
    2. 
        
  2. 02
    Write the spec first
    Before any code: what it does, what it doesn't, and the stack. A clear brief saves a week of rewrites.
    3. 
        
  3. 03
    Build in small loops
    One feature, one check in the browser, repeat. Project rules live in a file so every session starts from the same page.
    4. 
        
  4. 04
    Ship it, then tell the story
    This is where the marketer comes back. A build isn't finished until someone has seen it.
